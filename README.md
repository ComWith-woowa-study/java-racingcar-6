# 미션 - 자동차 경주

**<도메인 파악>**
1. 자동차는 전진 혹은 멈출 수 있다.
2. 각 자동차는 이름이 있다. 라운드 한번이 진행될 때 자동차(들)의 이름을 출력(5자 이하)한다.
3. 사용자는 몇 번의 이동을 할 건지 입력해야 한다.
4. 0부터 9까지의 숫자들 중 4 이상이 나올 경우에 자동차를 전진시킨다.
5. 우승자를 출력한다. 여러 명일 경우 쉼표로 구분해서 출력한다.
6. 사용자가 잘못된 값 입력 시 `IllegalArgumentException`을 터뜨리고 종료된다.

&nbsp;

**<엔티티와 관계>**
- `명사(엔티티 or 속성)`: 자동차, 이름(자동차), 라운드(몇 번의 이동), 사용자, 우승자
- `동사(행위)`: 자동차(들)의 이름을 출력한다. 특정 숫자가 나오면 전진하고 아니면 멈춘다. 라운드을 입력한다. 라운드을 진행한다. 우승자를 출력한다.

&nbsp;

**<역할과 책임>**
- `게임 진행자`: 자동차의 이름과 이동 횟수를 사용자에게 요구, 이름을 전달받고 자동차 인스턴스를 생성, 라운드 진행 시 자동차 이름을 출력, 전진 횟수 판단 후 우승자 출력
- `사용자`: 자동차 이름과 이동 횟수를 입력
- `자동차`: 전진, 멈춤

&nbsp;

**<프로그램 흐름>**
1. `GameManager.start()`
2. `InputView.readCars()` / `InputView.readRounds()`
3. `Player.of(names, rounds)`로 검증
4. Car 리스트 생성 → 라운드 수만큼 반복
5. 각 라운드에서 자동차별로 `isMoved()` 판단 후 `car.go()`
6. 매 라운드 OutputView.printProgress()
7. 종료 후 findWinners() → OutputView.printWinners()

&nbsp;

**<고민한 내용>**
1. 입력을 총 2번(자동차 이름, 이동 횟수)을 요구하고, 각 요구가 끝나고 입력을 해야한다. 각각의 내용에 대해 입력을 따로 받아야겠다고 생각했다(`readCars()`, `readRounds()`).
2. 각각의 도메인에 해당하는 예외 처리는 그 도메인에서 처리하도록 했다. 사용자는 입력받을 자동차 이름 검증(`validateCars()`), 입력받을 이동 횟수 검증(`validateRounds()`)을 수행한다.
3. 사용자와 자동차가 직접 대화하기에는 라운드를 진행하고, 우승자를 출력하고, 전진 여부를 판단하는 등 모호한 책임들이 많아서 `게임 진행자` 역할을 만들고 책임을 부여하는 것이 더 바람직하다고 생각했다.
4. 자동차가 이동하는 로직은 문제에서는 한 칸(bar 1개)만큼 이동하는 것이지만, 자동차들이 각각의 다른 이동 전략을 갖고 있다면, 예를 들어 어떤 자동차는 2칸씩, 어떤 자동차는 0.5칸씩 이동한다고 하면 ***"이동 전략"*** 이라는 인터페이스로 추상화하고 각각의 전략에 대해 구현하는 것도 괜찮다고 생각했다. 그럼 자동차 자체를 추상화할 필요 없이 전진하는 방식만 추상화해서 더 간단해지지 않을까 생각했다.
